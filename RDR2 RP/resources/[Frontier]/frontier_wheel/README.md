## Persistent weapons (next stage)
PR 79 must already be merged. Deploy matching inventory, wheel and VORP inventory changes and perform a full server restart. No SQL migration. Use /frontier_inv_test weapon_cattleman 1, weapon_lancaster 1, ammo_revolver 30, ammo_repeater 30; place guns in correct equipment slots, ammo in quick slots or satchel. Select actual owned gun through TAB, R reloads; quick rounds first, satchel after 2 seconds. Reload tops up to model capacity (6/14), can load a partial clip if belt stock is short; native prepaid reserve is used before further debit. On normal holster, gun item keeps its remaining checked-out rounds; switching weapons uses same release/draw process. Drawn weapon cannot be moved; holster first. The serial is the existing item instance UUID. /frontierweaponstatus reports native clip and allowance; /frontierweaponholster releases the lease. Gun Lab remains ACE gated and isolated; do not use both simultaneously.
Safety tradeoffs: server owns inventory deductions and caps client-reported remaining rounds to its lease; native shot reports are still client-observed and not full anti-cheat. Draw checks out stored rounds transactionally and resets stored count to zero; disconnect/crash/abandoned lease forfeits checked-out rounds rather than generating ammo. Native injection failures can likewise lose paid rounds. No automatic VORP weapon conversion, no legacy/native pool overwrite, no dual wield, custom ammo types or condition wear yet. Existing VORP reload and ammo polling pause during Frontier native ownership. Do not mix VORP weapons of the same ammo class with Frontier; use a clean character for testing. Additional guns can be carried as unequipped satchel merchandise, not drawn. No universal prevention of external weapon grants.
