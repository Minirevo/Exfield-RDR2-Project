# Frontier Jobs — first integration build
Apply sql/001_jobs.sql to the existing oxmysql database. Deploy the accompanying Inventory, Economy and Business changes together and start frontier_jobs after frontier_business and frontier_gathering. If the private server config is not tracked, add ensure frontier_jobs manually. Restart the full server so allowlists and exports reload.

## Flow
- Approach a town board or employer and use the Employment prompt (or /jobs). /myjobs shows persistent personal contracts anywhere. Boards share postings. Board props, map blips, employer coordinates and NPC models are provisional and require in-game calibration; the interaction is location-based, not dependent on the ped spawning.
- NPC logging/mining require on-site acceptance. Choose own tools or loaned equipment. Hunting/fishing may be accepted at any board. Work uses existing Gathering mechanics; deliver the specified actual inventory items to the correct employer. Supplies are taken in one atomic inventory operation; successful delivery pays the bank once. Existing inventory goods may be used; this is a delivery contract, not proof the player personally gathered every item. Daily per-character and per-template quotas limit generated wages. All loaned tools are non-droppable, non-transferable and cannot be stored outside the private toolbelt. They are returned on delivery, abandonment or expiry. Unresolved gathering claims block return. NPC stock remains in private contract containers; no market resale yet.
- In /business select an active company and choose Employment. Recruiters with hire permission can publish recruitment advertisements and review applications. Use existing Business hiring to send the actual invitation. One-time tasks require withdraw permission to escrow the entire fixed reward before publication. Workers accept at a board, arrange the work, submit completion, and the recruiter approves payment. No broad company permissions are granted. An employer cannot cancel an accepted/submitted task; an active worker may abandon it. Unsubmitted tasks expire and refund; submitted tasks stay pending review, with no automatic dispute resolution in this version.
- All irreversible effects are journaled by stable contract keys. One FXServer worker per database. Failed funding, returns, inventory commits and payments can remain pending for recovery. Admins should investigate persistent pending rows before changing state manually. Company liquidation integration, automatic facility task completion/temporary permissions, recurring shifts, NPC stock consumption/resale and further professions are follow-up work. No new money is generated for company tasks.

## Test
Run lua5.4 tests/rules.lua from this resource, node --check html/app.js, and syntax-check all changed Lua. Then use a disposable copy of the database and test on RedM:
1. Check all board and employer positions, NPC appearance, prompts, and waypoint native. Adjust config as needed.
2. Accept at a board (hunting/fishing only), attempt on-site jobs remotely (reject), then accept with and without tools at the yard/mine. Test loan in bag/belt, drop/give/store rejection, tool wear, full inventory, gathering and cancellation/expiry/reconnect.
3. Deliver insufficient goods, then exact quantity; verify stock, loan removal, bank receipt, repeated request and restart during pending inventory/payment.
4. Publish company recruitment and funded task; insufficient balance must not publish. Test application, two different workers racing acceptance, own company rejection, completion review, approval once, cancellation refund and worker abandonment.
5. Attempt forged client requests, wrong character/board/employer, revoked company permission, and recovery during restart.
This is not a live-tested release. Wages and coordinates are gameplay defaults, not calibrated final values.

## Business navigation and map hotfix
Employment & recruitment is now a dedicated Business sidebar page and is linked from Employees & ranks. Select an active company, open the page, then Open employment management. The server still checks hire permission. The Jobs menu now uses RedM GPS multi-route natives and map markers use existing game sprites for notice boards and employers. /jobmarkers rebuilds all markers and reports the count; /clearjobroute clears the current employment route. Routes also clear on arrival. No SQL change. Restart frontier_jobs and frontier_business after pulling; reconnect if the client still shows an old NUI. Verify six board markers and four employer markers in-game.

## NPC visibility and delivery hotfix
Employer NPCs initialize a RedM outfit, use a fallback model if needed, respawn if the handle disappears, and are independent of board props. Employer interaction reach is 8m (board reach remains 4m). /jobs opens the nearby location even if the prompt fails; /jobdebug reports nearest site, coordinates, distance and whether the NPC exists. Active NPC contracts appear at the top of the employer menu and in /myjobs with current satchel counts on open/refresh. Deliver directly from either menu, only within server-validated employer distance. Existing contracts are preserved. No database migration. Restart frontier_jobs. NPC models and coordinates still require live verification.
