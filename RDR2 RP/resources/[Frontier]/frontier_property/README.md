# Frontier Property v2
Fresh settlement resource. Requires OneSync, Frontier Core/Economy/Inventory, oxmysql.
Apply sql/migrations/001_settlements.sql to the existing schema; deploy the accompanying Inventory changes and restart Inventory, then ensure frontier_property. The Inventory/Economy allowlists already include frontier_property.
One FXServer worker per database; never run two copies. Do not reset relational tables on updates. If the old prototype has live data, export it separately before switching; no automatic import is provided.
The property market is global via /propertymarket (also reachable from the Frontier Trade window). /propertyshop opens the configured general-store catalogue only within 5m of a shop. Use kit from Frontier Inventory. Press E at camp, construction stack, or finished building; /propertymenu is an alternative. Use furniture inventory items inside your building. Placement keys are arrows, PageUp/Down, Q/R, Enter, Esc. All prices are cents, weights grams.
Defaults are populated in config.lua. Tax is proportional to area, weekly, grace one week. Expansions cost 15000 cents initially and rise by 50% each time; max radius 500 is configurable. Camp chest is managed by the property authorization hook.
Native asset sources: https://github.com/femga/rdr3_discoveries/blob/master/interiors/interiors_coords_and_hashes.lua and https://redm.info/props and https://github.com/femga/rdr3_discoveries/blob/master/objects/object_list.lua . Models and room anchors are candidates only. Field and pen entries are marker placeholders for later gameplay, not full fenced meshes. Several exterior categories reuse the same cabin model. No terrain/road/water authoritative geometry exists; town circles are conservative approximate defaults, not surveyed boundaries. Interior anchors, collision, IMAP requirements, furniture bounds and entrance offsets need a two-client RedM acceptance test before public launch.
Storage access is checked for every Inventory operation. Financial and item jobs persist intent before calling idempotent APIs. A pending job globally locks property mutations until reconciled; investigate database/receipt conflicts rather than deleting jobs. No automatic legacy migration.
Persistence uses dedicated relational tables and per-row transactional diffs; a single worker caches records at startup. Load-test before scaling to large servers. All players receive sanitized nearby public objects only; private furnishing data is sent to occupants. Default bucket range is reserved exclusively for this resource. Verify no other resource uses it.

Run Lua 5.4 syntax checks and tests/rules.lua; Node syntax check html/app.js. Then on a disposable RedM schema test two competing claims, permission revocation with an open chest, repeated item and money receipts, disconnect during construction, entry/exit and bucket isolation, furniture pickup with full inventory, co-owner approvals, sale and tax foreclosure. Current placement feedback is textual VALID/INVALID; field and pen are marker props, not functional agricultural systems. The shop is an independent Frontier shop menu at configured stores, not VORP inventory. Existing global trade menu links to a dedicated settlement market screen.

## Inventory compatibility fix
Production owns flour, meat, wood, iron_ore, coal, cooked_meat, wooden_planks and iron_ingot. Inventory no longer seeds competing material definitions. When Production registers, exact legacy definitions accidentally inserted by Inventory are adopted and updated in place; item quantities and slot records are preserved. Other definition conflicts are not silently overwritten. New construction uses wooden_planks. Existing construction stages and legacy planks items are retained as stored; if you have active old projects, finish or remove them before expecting the new material ID to apply. Restart Inventory, Production, Trade and Property in dependency order. No schema reset required.

## Height correction
Camp props and unfinished construction markers independently resolve local terrain height before freezing; unavailable terrain is retried. New exterior previews start on terrain using model bounds; manual height adjustment remains available. Preview confirmation saves the actual entity origin, and completed buildings/furniture use SetEntityCoordsNoOffset to restore it without another model-dependent offset. Existing completed objects use their saved origin; if previously placed at a bad height, use Relocate to correct them. GroundModelOffsets allows per-model correction if a model's bounds include a buried foundation. No SQL changes. Live terrain and model pivots require in-game validation.

## Collision diagnostics
Completed objects explicitly request model collision and enable entity collision; nearby streamed objects re-request collision if needed. Ghosts remain non-solid. Use /propertycollision near a problematic object to print its model and collision readiness in F8. Some native map drawables may not include standalone collision geometry; if a model remains non-solid after loading, it needs a different asset or a custom collision mesh. No invisible generic wall is added. This revision also retains the ground placement fixes from PR #35.

## Administrator testing commands
These require the server-side ACE `frontier.property.test` and `AdminTesting.Enabled=true` in config.lua. Example server.cfg: `add_ace group.admin frontier.property.test allow` (only if group.admin contains your trusted admins). Disable AdminTesting on public servers. Use in game with a loaded character, outside interiors.
- /propertymodels — list catalogue keys and camp prop keys.
- /propertyspawn cabin — spawn one temporary local test model in front of you, without settlement/database changes. Optional second argument is distance in metres (3–25). The object is removed on replacement, /propertyclear, interior entry, resource stop or after five minutes. Only the testing client sees it.
- /propertycollision — inspect the nearest test or property object in F8.
- /propertyfinish — instantly finish the nearest eligible unfinished construction within 20m. Optional building ID restricts selection. This permanently completes the normal construction record without charging additional materials; previously delivered materials are not refunded. Listed settlements and pending jobs are excluded. Use only on the test server.
- /propertyclear — remove the temporary test object.

## Crow Maps house assets
The installed frontier_assets resource streams free_house01, free_house02 and free_house03. Start it before frontier_property. Residential shack/workshop use free_house02; cabin/store/warehouse use free_house01. The third model is available for admin testing only until its dimensions and collision are verified. Separate interior routing remains unchanged; native shell windows/doors are not yet assembled. Use /propertyspawn free_house01, /propertyspawn free_house02 or /propertyspawn free_house03 to test, then /propertyclear. No SQL migration. Keep the original asset pack and escrow files intact; do not redistribute without permission.

## Expanded asset testing
All 25 drawable filenames currently in frontier_assets/stream are registered as temporary admin test candidates. Spawn names are inferred from filenames; archetype names and collision need live verification. /propertymodels lists them in numbered alphabetical order. /propertynext cycles forward (or /propertynext 1 starts at the first), /propertyprev cycles backward. /propertyspawn <name> [distance] tests a specific asset; /propertyclear removes it. Each test replaces the previous temporary object; none changes the database. Multipart ranch/stable/Caliga Hall models are tested separately, not assembled: their final offsets, doors, collision, dimensions and furnishing logic require verification before adding them to the construction catalogue. Existing construction entries are unchanged.

## Multipart building tests
ACE-gated /propertyspawn bee_stable, bee_mainhouse, bee_workerhouse, caligahall now spawn complete temporary assemblies. Each part is spawned separately but shares the first part's grounded origin and common heading; subsequent components are never independently ground-snapped. Offsets in TestAssemblies are local-space values, initially zero and unverified. /propertycollision reports every part. /propertypart 2 z -0.1 adjusts component 2 down 10cm; x/y/heading also supported. /propertyparts prints offsets in F8 for reporting. Adjustments affect temporary objects only, reset on respawn, and cannot create new objects or change persistent buildings. /propertyclear, replacement, interior entry, resource stop and five-minute expiry clean up the full assembly. The normal catalogue and SQL are unchanged pending visual/collision validation.

## Persistent test sessions and keyboard alignment
Temporary test models no longer expire automatically. They are mission entities and are restored at their exact stored transforms if removed while within 100m. Replacement, /propertyclear, interior transitions and resource stop still clean up all test objects. /propertyedit [part number] starts keyboard editing (default component 2), arrows move in assembly-local X/Y, PageUp/Down changes Z, Q/R rotates, E cycles components, Enter or Escape exits while retaining offsets and prints /propertyparts. /propertystep 0.01 changes movement precision. The selected component is translucent. All adjustments are local and temporary. No catalogue or SQL changes; native controls and asset alignment remain to be tested in RedM.

## Physical buildings and plot furniture
Before restarting, import sql/migrations/002_physical_furniture.sql (idempotent). Physical construction uses calibrated multipart assemblies, no new teleport interiors; existing legacy interior records and stages are retained for recovery. Old furniture is not teleported into an arbitrary new room: recover it to inventory from the camp menu, then place it on the plot. Existing visits still exit safely. New furniture is stored in fp_plot_furniture; indoor association is derived server-side from completed buildings and model-local configured bounds (provisional estimates, not exact collision geometry). /propertybounds reports actual model dimensions for refining the config. Furniture is allowed anywhere within the plot, with indoor/outdoor labels, nearby move/pickup via /propertyfurniture; associated furniture moves with a relocated building, and remains on the plot on demolition. Existing furniture item definitions are unchanged. Door locks are not yet implemented for physical models. Construction prices/radii for new buildings are provisional. Existing warehouse changes to stable shell and may require relocation; existing stages and saved origins remain. New plot furniture and legacy furniture both count toward foreclosure. Back up database before migration.
