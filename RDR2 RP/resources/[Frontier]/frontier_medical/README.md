# Frontier Medical — guarded native damage adapter

## Deployment
Deploy all changed resources and restart the entire server with players disconnected. Existing SQL migration 001_medical.sql and earlier Needs migrations remain required; **no new SQL migration**. Existing medical JSON is upgraded without erasing injuries. Stop/disable frontier_damagelab and remove its test convar, keep vorp_medic and vorp_metabolism stopped. Start frontier_inventory, frontier_needs, frontier_medical, and frontier_hud in normal order. VORP Core remains the provider for actual death/respawn, not ordinary injury/unconsciousness.

## Tested design from the lab
Guarded mode uses an effective native max-health buffer requested at 5000 (live readback 5550), per-frame health refill, and flags 263, 340, 388. Accept the effective cap; save and restore original settings with bounded correction, including failure/reconnect warning. Native HP is a sensor, not a gameplay health reserve. Frame-level raw losses, not percent of inflated HP, are aggregated by region/type and sent in bounded 500ms batches. The existing AI/network event counts are intentionally not added as damage. Optional weapon/bone/source flags only classify trauma; unknown bone defaults to chest. Fall uses actual falling rather than ragdoll. Native death bypass is still possible (untested lethal execution/fire etc.); if setup fails or state heartbeat is stale, protection is removed rather than granting uncontrolled immunity. Engine death falls back to the provider. This is not a native death interception guarantee or an anti-cheat solution.

## Physiology
Seven body regions, existing wounds/bleeding, fractures, pain, temporary analgesia, nutrition-dependent recovery. New cumulative tissue trauma (raw damage * 4, region multiplier) gives blunt damage its own unconsciousness/fatal route. Trauma >=650/1000 causes unconsciousness, <=450 allows wake if other reserves permit, >=1000 fatal. These are configurable gameplay values, not real-world thresholds. Raw damage is divided by 3 to derive wound severity independent of buffer. Fire and bite are preliminary classifications. Large water-related loss or recognized drowning cause while in water sets a single drowning flag per batch, decreasing oxygen 75/1000 rather than creating thousands of wounds. Oxygen <=350 knocks out, zero is fatal, recovery after 5s without drowning. Drowning detection is heuristic; rescue physics and fire need live tests. Needs applies deprivation 10 units per existing starvation/dehydration percentage point every ~15s. No native HP drain when Medical is active; deprivation recovery requires both nutrition reserves. No feeding unconscious patients yet. Native health display is hidden in Frontier HUD while Medical is active; use examinations instead.

Only server-persisted fatal medical state requests native death, after removing guard flags. Persist nativeSeen separately: do not reset a fatal medical state before provider actually observes death and later reports alive. Existing provider death (including a native bypass) is respected. VORP respawn/death UI remains as a terminal lifecycle adapter; fast death/respawn between provider polls, native guard and admin revive interactions require live testing. No native lethal damage resurrection hack.

## Usage
/medical for self, /medical <server ID> for nearby patient within 3m, same bucket. Examine region, check pulse and breathing. First aid uses real inventory supplies and receipt-backed application: bandage controls bleeding, splint stabilizes fracture, tonic temporarily suppresses pain. Splints craftable at carpentry. Quick Medicine wheel auto-selects eligible self wound. Unconscious patients can be treated by conscious players. Unconsciousness blocks work, item use, firearm draw/reload and client movement/firing; does not cancel firearm release or ammo recovery. Unstabilised fractures limit labour. No new advanced treatment, CPR, oxygen delivery, surgery or doctor licences yet. /frontiermedicalstatus reports adapter mode, native buffer and report queue without exposing hidden physiology.

## Reliability and limits
One inflight batch is acknowledged only after persisted JSON revision CAS; sequence stored alongside state to deduplicate retries, bounded by life/session token. No separate SQL receipt table needed. Clients can still spoof/withhold own hit observations, and unacknowledged RAM batches are lost on disconnect or crash. Client cap limits overload. Server state remains authoritative for recorded injuries/death, not trusted hit capture. If DB is unavailable, guard expires after 15s without state and native fallback applies. A fixed oxygen penalty per accepted batch intentionally avoids frame-rate scaling; network lag can slow that penalty. Existing treatment outbox semantics remain; a spent item may be ineffective if condition changed. No offline progression. Native cap/flags restoration requires live verification; reconnect if warning occurs. Before deployment, reconnect after lab to avoid retaining a modified native max.

### Guard startup recovery
If a native setup or refill check fails, the adapter records ordinary unprotected health deltas while waiting five seconds before retrying. A failed cleanup still blocks further native settings changes on that ped until reconnect. Startup waits briefly and observes the Core spawn event. Effective maximum and actual attainable refill HP are separate; e.g. maximum 5550 and refill 5000 are acceptable. /frontiermedicalstatus now includes fallback/guarded/inactive mode, server state age, retry timer and last error. Fallback preserves wound reporting but cannot prevent native death. Native cap changes are not themselves wounds. Run `lua5.4 tests/damage_rules.lua` for pure readback and fallback regression. Live native behavior still needs verification.

### Continuous unconscious posture
The client initiates ragdoll on collapse and refreshes its timer every frame during unconsciousness, instead of reissuing a collapse every two seconds. If another native action interrupts ragdoll, the client retries at most every 150ms while eligible. Waking, native death, stale medical state, mounting, vehicle occupancy or being attached to another ped stops the medical ragdoll maintenance; it does not clear unrelated native tasks. Ground collapse and natural recovery require live RedM animation verification.

### Visible injuries and player feedback
The body diagram alone selects regions (including keyboard activation). At a glance it shows visible wound types and whether bleeding is apparent; exact severity, bleeding intensity and fracture assessment require a close examination. Visible bleeding can be bandaged immediately. Splinting still requires examination; self pain tonic can be used without it, other patients require examination. Server revalidates eligibility and patient life before treatment; inventory receipts are unchanged. The chart refreshes with medical ticks and after treatment. A new injury in an already wounded region preserves previous visible wound categories. Owner-only qualitative feedback reports confirmed hits, bleeding, faintness, pain, breathing distress and deprivation without numeric medical reserves. Subtle CSS vignette and symptom chips do not affect controls or gameplay balance. Feedback clears on unconsciousness, death, unload or expired state. Penetrating classification can represent a bullet or another puncture; exact weapon/bone classification remains best effort. No SQL migration. Live test a shot, immediate visible wound, bandage without exam, detailed exam, symptoms worsening and clearing, nearby patient and menu refresh. Run tests/observations.lua for model regression.

## Professional medicine (V2)
**Apply sql/migrations/002_professional.sql before starting Medical.** Deploy frontier_inventory, frontier_skills and frontier_medical together and restart the whole server. Existing state JSON and 001 migration are retained. The native adapter is unchanged.
- Internal bleeding continues after external bandaging. Regional organ injury impairs circulation and chest oxygenation. Repeated limb injuries accumulate bone damage; a temporary splint does not cure a new fracture. Deep/contaminated wounds, retained projectiles and fragments prevent normal healing until addressed. Retention is a deterministic gameplay approximation based on eligible damage batches, not actual trajectory or object detection. Existing wounds are not retroactively assigned hidden complications.
- Normal players retain first aid. A licensed medic (ACE frontier.medical.medic) has clinical assessment, instrument-based vital signs, and restricted treatment. Surgery requires another medic unless self-testing is enabled. Stethoscope and thermometer are reusable. Temperature is a baseline placeholder until fever/infection is implemented. No hospital location restrictions, equipment wear, NPC doctor fallback, anaesthesia or infections yet. Supply acquisition is admin test grants for now, not a new production/shop chain.
- Procedures: clean wound with antiseptic, remove retained object with surgical kit + surgical supplies, stop internal bleeding with same supplies, treat organ injury once internal bleeding controlled, close cleaned wound after objects/internal bleeding removed with suture kit, realign fracture with medical splint, morphine for pain, saline for temporary circulatory support. No procedure restores a dead patient. Timed gameplay precision checks use server elapsed time, one to three stages. Failures spend supplies, wide misses cause complications. Closing/disconnect/expiry resolves as paid failure, not a refund. Server-owned challenge and time checks are not proof of human input; network latency affects timing. Persisted operation and inventory receipt are matched before revision-checked effect; successful other-patient procedures award idempotent Doctoring XP (separate from Medicine crafting). Skill widens timing tolerance. Tests do not award XP.
